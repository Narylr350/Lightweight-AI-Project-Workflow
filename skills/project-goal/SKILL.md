# Project Goal

为一次自主执行准备目标模式提示词，是可选的手动入口，不是普通开发的前置步骤。

## 边界

- 仅用户明确调用时使用；长任务、自动推进、普通的“继续”不构成调用。
- 默认只读：核验项目和讨论方案，不改文件、分支或系统，不安装依赖，不执行 build / test / format。不调用运行时的创建 / 更新目标工具，也不自动进入 project-work。
- 生成提示词不等于确认架构、授权实施或授权提交 / 推送 / 发布。权限来自用户当前明确授权及有效项目指令，不能从任务规模推定。
- 不要求运行时必须支持某个 API。输出可由用户交给所用客户端的目标模式；本 skill 不实现调度、目标状态存储或任务管理系统。

## 准备目标

1. **界定对象**：根据用户请求确定是单模块、一项跨模块能力，还是整个项目阶段。用户已给明确对象时不再询问；范围不明确且会影响交付时，先问一个最高影响问题，不默认扩成整个项目。
2. **核验事实**：读取 .ai/PROJECT.md、.ai/CONSTRAINTS.md 和 Git status / log / diff；按需读 .ai/TECH.md、.ai/VALIDATION.md 及直接相关代码。当前对话中的已确认决定可以复用；Next / handoff 只是线索，不充当总体路线。没有基线时仍可整理已有事实，但不自动初始化或把候选方向当已确认架构。
3. **形成实施依据**：沿用 [project-work](../project-work/SKILL.md) 的“模块交付”规则，明确结果、实现路径及理由、关键前提、有限切片及依赖。阶段目标还要说明模块协作和顺序依据。复用有效方案，只调查影响方案成立的未知；不全仓审计，不预先设计完整类树。
4. **处理决定与未知**：影响目标、支持范围、整体架构或验收口径的未决问题先交用户决定。技术未知可通过只读资料 / 源码调查缩小；需要实验或真实操作时说明证据需求与权限。尚未解决时输出待决定项，不生成把这些内容藏成默认值的可执行提示词。用户明确要调查目标时，可把取得这些证据本身定义为目标，不预先承诺实现。
5. **检查收敛性**：每个切片对应交付缺口，调查有证据要求和结束条件，前置任务服务真实路径。完整项目目标只覆盖已确认范围，不使用“持续完善”“把所有问题解决”等无结束边界的表达。

已有需求、方案与权限足够明确时直接输出，不增加一次形式确认。提示词只承载本次执行必需的上下文，不复制整份基线或 skill。

## 输出目标提示词

信息足够时，简短说明目标覆盖范围，然后在一个可复制的 Markdown 代码块中给出以下内容，替换为真实项目事实，不留待填占位符：

- **工作区与事实源**：目标项目路径、有效指令及相关基线路径；启动时重新核验 Git 和未提交改动归属，不把生成时的快照当永久事实。
- **目标与意义**：交付的用户能力或调查结果，以及为什么做。
- **范围与完成条件**：本次支持范围、不包含的工作、有限且可观察的验收项与验证方式。跨模块目标同时有模块完成线和整体完成线；单个切片通过不等于整体完成。
- **实施依据与顺序**：已确认架构、职责 / 状态 / I/O 边界、复用能力、选择理由；有限切片的产出、依赖和验收。未验证但不影响用户决策的技术前提，显式列为先验证的步骤及所需证据。
- **自主执行权限**：可自行处理的实现细节和已授权操作；目标授权不扩大原权限，提交、推送、发布、系统或真实设备操作按当前授权处理。
- **推进与恢复**：每个切片后对照目标完成条件说明已满足项、剩余缺口和下一步必要性；继续时从目标、基线和 Git 恢复，而非只沿 Next。遵循 project-work / project-finish，Next 只交接最近一步。
- **结束与求助**：验收满足时结束目标，不追加优化。缺少环境、权限或外部条件时，指出阻塞的验收项、已有证据和用户需提供的最小帮助；只继续已授权且不依赖该阻塞的工作。承重前提被推翻或原架构无法交付时，停止依赖它的实施，给出修订依据和取舍；涉及范围、架构或完成标准变化时等用户决定。必要安全边界不因赶交付而省略，也不通过额外旁支研究无限延长目标。

提示词之后只列确有必要的执行前条件。输出后结束本次调用，不自行创建目标、写入 .ai/ 或生成 handoff。
